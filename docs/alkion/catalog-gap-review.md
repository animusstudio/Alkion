# Catalog gap review

Use this rubric for a private supplied-name audit. Keep supplied names, proposed
personal mappings and corpus extracts outside the repository and APK assets.
A search hit is a candidate for review, never automatic equivalence.

Record the catalog digest/revision, browse classification digest/revision,
interface locale, exact query, active view and filters before assessing a gap.
Repeat each query in **All**, with filters cleared; inspect the family and
concrete execution, equipment, facets and measurement profile. Distinguish
source observations from the proposed catalog mapping.

| Classification | Evidence required | Disposition |
| --- | --- | --- |
| Vocabulary | A compatible concrete execution exists, but the supplied term does not retrieve it; a canonical query does. | Propose a reviewed alias with locale and explicit target. |
| Filtering | The execution is reachable in All/search, but a supported selected scope incorrectly excludes it. | Fix the browse/search path with a synthetic regression case. |
| Metadata | The execution exists, but reviewed equipment, activity or muscle classification is missing or wrong. | Propose corrected classification separately from anatomical evidence. |
| Definition | No compatible concrete execution/measurement context exists after vocabulary and scope review. | Propose a scoped dataset addition; do not manufacture a match. |
| Ambiguous | Several executions could fit, or source detail cannot establish compatibility. | Retain unresolved; record the exact detail needed. |

A private review row records: supplied name; candidates (variant ID and revision);
classification; exact/approximate/unresolved mapping; compatible measurement
profile and context; rationale; evidence/query and scope; reviewer and decision.
An approximation must state the difference and must not reinterpret recorded
load as assistance, added load or distance. Dataset changes and redistribution
clearance are separate from this usability change.

Report totals by classification and mapping status, including every supplied
name once. Coverage means the supplied use cases are accounted for; it does not
establish a universally complete catalog. Android discovery timing and correctness
are separate evidence from this review.
