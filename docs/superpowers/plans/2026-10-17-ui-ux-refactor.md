# Alkion UI/UX refactor plan

Date: 2026-10-17. Status: **approved scope and visual direction; T1–T7 source reviews PASS**.

## Outcome

Refactor the existing Alkion Android experience to improve clarity and translate the approved Reps specimen and Animus branding into Flutter before final owner-device qualification. The source audit is recorded in the [design brief](../specs/2026-10-17-ui-ux-refactor.md). The owner selected UI as the priority and direct Flutter implementation. Keep the current navigation and workflows; this is a visual translation, not a new visual world.

## Decisions and non-goals

- Keep the current four-tab shell, profile overlay, in-tab Plan editors and focused live-workout model unless approved evidence requires a bounded change.
- Map the established semantic roles into Flutter Material 3 theme tokens: ink/bone surfaces, neutral primary action, coral workout identity, blue focus/info and distinct status roles. Replace Space Grotesk display with Hanken Grotesk; retain Hanken for interface text and JetBrains Mono for values. Translate the specimen's 10 dp controls, 16 dp plates and 4/8/12/16/24/32 dp spacing through existing components. Preserve Android system Back and inset behavior, dark/light readability, exact workout values, unknown coverage, 48 dp live targets, text scaling, locales and reduced motion.
- The opening signup/login page and returning-session flow belong to the later Animus sync work. Keep local/offline use explicit; make no auth, transport or account attachment changes here.
- No new IA, features, dependencies, assets, visual identity or release claims. Data-preservation operations are outside this UI plan; coordinate presentation copy with the approved recovery requirements.
- Each surface task owns its localization strings in `app/lib/l10n/app_{en,de,es,it}.arb`; update all four together and regenerate localization output only through `make -C app gen-l10n`. Task owners add/update only keys for their surface. T8 owns the cross-locale parity check.
- Each surface task T1–T7 also owns updates to the exact focused test files listed in that task. When a focused test file covers multiple tasks, its edits are serialized: the earliest task needing a change owns and completes it, then hands it off; later tasks may update it only after that handoff. T8 owns its separately listed integrated acceptance and locale-parity tests.
- Shared main/profile/recovery files may overlap concurrent Android readiness changes. Serialize edits to `app/lib/main.dart` (T2), `app/lib/ui/profile_screen.dart` (T6), and `app/lib/ui/alkion_recovery/{recovery_screen.dart,recovery_app.dart}` / `app/lib/ui/alkion_transfer/transfer_screen.dart` (T7) with those changes; no simultaneous ownership. T7 owns presentation only, never storage, transfer, restore or domain behavior. Shared widgets have no blanket task ownership: the earliest task that needs a shared widget owns that file's change, and completes/hands it off before a later task edits it. Each widget is named in its surface task; no wildcard widget permission.
- Tests listed below are focused acceptance for the implementer; they have not been run as part of this docs-only planning task.

## Acceptance

See A1–A7 in the [design brief](../specs/2026-10-17-ui-ux-refactor.md). Implementation must preserve current functionality, accessibility and data truth, and must end with affected synthetic Android device checks on the selected candidate before owner qualification.
